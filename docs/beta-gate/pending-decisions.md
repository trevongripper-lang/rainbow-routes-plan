# Phase B retention / anonymisation decisions — RESOLVED

Date resolved: 2026-07-28. All rows below are approved for Phase B
implementation. Rows tagged **"legal review pending"** are engineering-safe
defaults that must be re-confirmed by qualified counsel before public beta;
the code and disclosures will label them "implemented — legal approval
pending" and MUST NOT be described as legal conclusions.

Legend: **auto** = fully automated deletion step; **manual** = operator-owned
step that keeps the deletion job in `awaiting_manual` until closed;
**retention** = background job (not tied to a specific account deletion).

## Cross-cutting engineering rules confirmed for Phase B

1. **Preflight profiling done.** Orphan-UUID audit ran against production (2026-07-28); all 19 user-reference columns audited return 0 orphan rows. FK backfills can use `NOT VALID` + explicit `VALIDATE CONSTRAINT` with no data remediation needed.
2. **NOT NULL → NULL changes** on `trip_settlements.{from_user,to_user,created_by}`, `trip_stays.user_id`, `trip_flights.user_id`, `trip_tickets.user_id`, `trip_ratings.user_id`, `trip_poll_votes.user_id`, `trip_polls.user_id`, `trip_costs.user_id`, `promo_redemptions.user_id`, `storage_object_trip.uploaded_by`, `comments.user_id`, `trip_events.added_by`, `destinations.unlocked_by`, `notifications.user_id` are ONLY applied after: (a) UI review to render "Former member" instead of crashing on null, (b) RPC/trigger review to tolerate null actor references, (c) RLS-policy review confirming null does not widen access, (d) export/calculation review, (e) regenerated `src/integrations/supabase/types.ts` propagated to callers.
3. **Constraints via `NOT VALID` → `VALIDATE`** where the destination table has any historical row, to avoid long locks on large tables.
4. **Rollback notes** are provided per migration but do NOT restore erased personal data. Once anonymisation runs, the personal columns are lost.
5. **Storage cleanup deletes and verifies actual objects** in `destination-covers` and `destination-cover-drafts` using `storage.from(bucket).remove([...])` followed by a listing probe. Mapping-row deletion in `storage_object_trip` is not sufficient.
6. **Auth-user deletion is the last automated step.** The deletion job may only mark itself `completed` when every automated step is `done` AND every manual step is `done` or `retained_by_processor`.
7. **No PII in deletion job logs, step errors, or audit receipts.** The audit receipt is an opaque UUID and only records step keys, statuses, timestamps, and non-PII error summaries.
8. **Shared balances and settlements must be arithmetically unchanged** after actor-column nulling. A pre/post `SUM(amount_cents)` invariant is asserted per trip in the deletion job and in the regression test.
9. **Legal-review gate**: D-3, D-4, D-11, D-12, D-13, D-14 remain marked "implemented — legal approval pending" in code comments AND in user-facing disclosures until counsel confirms.
